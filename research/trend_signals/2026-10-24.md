# Trend signal — 2026-10-24

## Signal: `occlusion_count`

A fresh Shorts signal suggests that fast **count-under-motion / count-under-occlusion** challenges deserve a new test rather than reviving the old V6 `moving_count` unchanged.

- The signal is unusually stronger than the channel's same-day/new nearby uploads, so the counting mechanic itself is worth testing, while not assuming causality from one creator.
- Separate current puzzle activity still shows recurring short, immediately legible visual tasks (spot-the-difference and compact maze formats), reinforcing the low-instruction / instant-challenge pattern rather than long setup.

## Difference from current V7

Current V7 proven: `wrong_motion`, `animated_maze`, `memory_shuffle`, `spot_difference`.

Current V7 experiments: `physics_error`, `portal_path`, `laser_core`, `flow_field`.

`occlusion_count` is different: the viewer maintains a changing quantity while objects briefly disappear behind gates/tunnels/containers and re-emerge. It is not trajectory prediction, maze solving, anomaly spotting, or flow tracing.

This should **not** simply restore old `moving_count`; that family previously underperformed. The proposed test changes the mechanic to active conservation/accounting under occlusion with a stronger visual payoff.

## Proposed original format

Hook in frame 1: **“HOW MANY COME OUT?”**

- 6–12 glowing balls enter 2–3 moving gates/tunnels.
- During occlusion, deterministic split/merge rules alter the count (for example: one gate duplicates every second ball; another diverts one ball into a hidden lane).
- Keep all rules visually inferable before occlusion; no arbitrary hidden answer.
- 6–8 s solve/run phase, then a fast transparent cutaway/replay reveal showing the exact accounting.
- Optional A/B/C answer chips appear early, but do not pause motion.
- Aim for a seamless reset so replay naturally rechecks the count.

## Free implementation

Python + NumPy for deterministic particle/state simulation; OpenCV/Pillow for gates, trails, labels and cutaway reveal; FFmpeg for final encode/audio. No paid model, asset, or service required.

## Expected benefit

- Combines a currently strong counting signal with satisfying continuous motion.
- Creates a clear first-frame question and a reason to watch through the reveal.
- Replay is functional: viewers can recount and verify rather than merely rewatch decoration.
- Mechanically distinct from the current V7 pool.
