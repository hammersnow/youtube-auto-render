## Proposed family: `minimum_moves`
Show a small mechanical/digital state puzzle immediately and ask **`MINIMUM MOVES?`**. Animate only legal operations while a compact move counter runs. At ~6-8 s, reveal the optimal path rapidly, ending on the solved state and exact minimum.

Original procedural variants:
- segmented counter: reach target using constrained +1/+10/rotate operations;
- ring/gear state: align all markers with the fewest rotations;
- token rail: move colored tokens to target slots with one empty space;
- switch grid: one tap flips a deterministic local pattern.

Do not reproduce a creator's exact puzzle, geometry, target, artwork or solution. Generate states and solutions procedurally.

## Why it is new vs V7
Current V7 proven families are `wrong_motion`, `animated_maze`, `memory_shuffle`, `spot_difference`; experiments are `physics_error`, `portal_path`, `laser_core`, `flow_field`. `minimum_moves` adds **optimization/strategy reasoning** rather than visual anomaly detection, tracking, path following or physics prediction.

## Expected benefit
- First-frame comprehension: start state + target + `MINIMUM MOVES?` are visible immediately.
- Built-in retention: viewers mentally search while the counter creates tension.
- Strong reveal: optimal move sequence provides an objective answer rather than subjective payoff.
- Replay potential: viewers can rewatch to verify the optimal sequence.
- Large procedural state space reduces repetition and supports originality.

## Free implementation path
Python + NumPy for state generation and BFS/A* shortest-path solving; OpenCV/Pillow for rendering; FFmpeg for H.264/AAC. No external footage, paid model or paid API is required.
