### Why it is new for V7
Current strategy families are `wrong_motion`, `animated_maze`, `memory_shuffle`, `spot_difference`, `physics_error`, `portal_path`, and `laser_core`. `direction_lock` is not path finding, object tracking, memory, difference spotting, or a deliberately wrong physics event. The puzzle is **perceptual ambiguity**: the same motion can be interpreted as clockwise/counter-clockwise until a depth cue resolves it.

### Original implementation idea
Hook on frame 1: **"LEFT OR RIGHT?"** over a symmetric rotating object (ring, fan, abstract cat-like silhouette avoided to prevent copying). Build the object from procedural radial geometry. Remove decisive depth cues for ~5–7 s, then briefly add an occlusion/highlight/depth marker that locks the direction. Immediately remove the cue and return to the opening phase so the final frames loop into frame 1.

Optional variant: three rotating rings; ask **"WHICH ONE CHANGES DIRECTION?"** although no angular velocity changes—the perceived reversal is induced by ambiguous shading/occlusion. This creates a comment-worthy disagreement without misleading the reveal: reveal the depth cue and explain visually which interpretation was intended.

### Expected benefit
- New perceptual-puzzle axis instead of another trajectory/physics family.
- Motion exists from frame 0; no setup dead time.
- Naturally replayable because viewers can try to force the opposite perceived direction on loop 2.
- Language-light and sound-independent.

### Free implementation
Python + OpenCV/NumPy/Pillow only: polar/radial point generation, affine rotation, alternating occlusion masks, gradient/highlight cue, FFmpeg encode. No paid assets/models/services.
